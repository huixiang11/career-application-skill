# 岗位发现与核验

本模块由代理使用当前可用的网页搜索、浏览器及已授权招聘数据工具执行，不依赖额外看板、抓取服务或付费 API。它是搜索工作流，不是已接通所有招聘平台的爬虫。

## 1. 从用户目标生成检索条件

复用当前对话里已明确的信息，提取：目标职位、可接受的相邻方向、地区、招聘类别、届别、学历、专业、必需条件和排除项。区分“只考虑目标城市甲”和“目标城市甲优先”；前者是硬限制，后者是排序偏好。未确定的政治面貌、薪资或到岗信息保持未知，不阻塞公开岗位发现。

不把转正实习自动归为正式校招；记录其录用路径。搜索范围跟随最新用户要求，不能永久排除实习或永久限定某一届。

## 2. 两条搜索路径

**用户指定单位**：集团官网 → 招聘门户 → 对应届别或批次 → 具体用人单位 → 具体岗位。先搜指定范围，暂无结果时报告范围和限制，再将相邻单位作为补充。

**用户指定方向**：岗位名称簇 → 有相关职能的单位 → 官方招聘公告及职位列表 → 具体 JD。避免只搜索用户原话或只找到头部公司。

根据实际目标选用以下名称簇，不默认全部搜索：

| 方向示例 | 名称扩展方法 | 核验重点 |
|---|---|---|
| 技术岗位 | 标准职称、技术栈名称、相邻工程岗位 | 职责、技术要求和年限 |
| 业务岗位 | 业务名称、岗位职能、行业称呼 | 是否销售性质、个人职责和考核 |
| 职能岗位 | 职能名称、部门名称、专员或助理称呼 | 专业、证书与实际工作内容 |

以上是通用方法，不代表任何使用者的默认求职方向。

组合查询示例（按当前用户条件替换，不固定年份）：

- `单位全称 毕业届别 校园招聘`
- `城市 岗位名称 毕业届别 招聘`
- `单位简称 目标部门 招聘`
- `site:已核验招聘域名 岗位名称`
- `site:edu.cn 单位全称 毕业届别 招聘`，用于补充公告与附件线索

每条查询用少量相关词，同义词分开搜索；无结果时先移除软偏好或更换称呼，不放宽硬资格。检索无年份的招聘入口以补充漏项，但具体岗位仍须核对届别。

## 3. 渠道选择与访问失败

- 国内校招以公司官网、招聘系统、国资及主管部门招聘公告、高校就业网为主要路径。商业平台和公众号转载作为线索，尽量追溯原始公告；找不到原文就保留其来源等级。
- AI 方向优先结合 Offer岛，具体调用前按其当前 Skill 处理鉴权与字段。没有 key、额度不足或无结果时继续官网与公开检索，不伪造鉴权或因一个平台失败结束任务。
- 对前程无忧校招专题、北森、Moka、飞书招聘等，先读取当前页面链接、岗位筛选及页面公开数据。接口路径以现场观察或当前官方文档为准，不套用网上的旧接口。
- JavaScript 页面只返回空壳时用浏览器读取；图片公告查看图片，PDF 岗位表阅读附件；保留公告与具体附件之间的对应关系。
- 海外需求可评估 JobSpy 等工具，但先核实平台覆盖、版本与运行依赖。其支持某个国家不等于覆盖该国主流招聘平台。不要为普通搜岗任务自动安装项目、飞书同步工具或代理服务。
- 登录或验证阻断时换可访问的官方来源；确需账号才说明所需登录。429 按服务提示退避，短暂错误有限重试；不要持续轮询或通过更换身份规避限制。

## 4. 岗位记录和去重

普通查询在上下文中维护结果即可；用户要求保存清单或持续跟进时，再写入工作区。最小记录字段：

`company, hiring_unit, title, job_id, city, recruitment_type, cohort, qualifications, published_at, deadline, source_url, jd_url, apply_url, checked_at, availability, eligibility, evidence, next_action`

- `source_url` 是信息出处，`jd_url` 是职责详情，`apply_url` 是申请入口；三者可相同，也可分别记录。没有直链时给官方列表及操作路径，不能拼造职位 ID 或链接。
- `checked_at` 是本次访问时间，不替代发布时间；转载时间不视为重新开放。日期不明填未知，动态“招满即止”保留原表述。
- 优先使用招聘系统、具体用人单位和岗位 ID 识别同一职位；无 ID 时比对单位、岗位、地点、届别与 JD。跨平台转载归并来源；职责或资格有差异时保留不同记录。
- 清理 URL 时只删除明确的追踪参数；保留岗位 ID、租户、届别、查询参数和 SPA hash 路由。不可把不同职位链接截成同一首页。
- 招聘状态与用户投递状态分开。刷新只更新核验信息，不覆盖用户的已投、面试或拒绝记录。

## 5. 状态判断

| 状态 | 需要的证据 |
|---|---|
| 官方公告期内 | 官方对应批次公告与截止信息支持当前仍在招 |
| 系统显示可申请 | 具体职位可打开且显示申请入口，未见截止提示；不保证最终能提交 |
| 待核实 | 仅有转载、缺完整条件、公告与系统冲突或入口无法读取 |
| 已结束 | 明确截止时间已过、结束公告或岗位关闭提示 |
| 历史参考 | 旧届次或旧岗位，仅用于了解招聘方向 |

HTTP 200、申请按钮存在和搜索引擎最近抓取都不能单独证明有效。截止已过但按钮仍在时，标记已结束或冲突待核实，不能直接列入可投。用户资格另列“符合／条件待确认／不符”，不与岗位开放状态混淆。

## 6. 排序与交付

先过滤明确不符的硬条件，再按目标职责、真实经历支持、地点偏好、截止紧迫性排序；无数据时不计算录用概率。临近截止不意味着适配度高。

结果表呈现：单位及岗位｜地点与届别｜资格及匹配理由｜状态与截止｜投递链接。先交付可行动结果，再列待核实线索和关键排除原因。注明核验日期、搜索范围以及尚未访问成功的渠道；不要声称穷尽全部岗位。

用户指定数量时尽力达到，但不以不符条件岗位凑数。未指定数量时给一组高相关结果；覆盖主要名称簇和指定单位、后续查询持续重复时可以结束，并说明剩余缺口。刷新任务优先报告新增、结束、条件变化和临期项；只有用户请求才建立定时提醒。

## 维护检查案例

- 同岗位有三个转载链接：合为一条并保留官方来源；不同岗位 ID 不盲目合并。
- 毕业前一年发布的目标届别公告：按毕业届别纳入，不按发布年份排除。
- 目标城市甲是硬限制，发现其他城市乙岗位：不能放进主推荐；目标城市甲优先时可明确列为异地补充。
- 截止日期已过但按钮可点：不能称仍可投。
- 数据源只返回公司名称与职位标题：属于线索，不生成不存在的 JD、薪资或资格。
